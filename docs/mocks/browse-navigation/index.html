The browsing design guide is the implementation reference, including the later wide-screen concepts, bounded player panel, artwork grids, metadata columns and compact list items arranged across rows. This prototype retains its earlier equal-width panels and simplified controls.

One browsing system. Different pages for different things.

The current app asks people to learn several meanings for the same album, artist or playlist row. Make opening content predictable, then keep listening fast through explicit Play and queue actions. Retain Kalinka’s Home, music sources, pinned catalogs and persistent player.

What the code does today

  • Album and playlist row taps expand in search, but navigate when a BrowseNavigationScope is present. The same row can still expand through its chevron.
  • Home previews disallow expansion; catalog pages permit it; nested artist results introduce another exception. Collections also have a separate inline editing flow.
  • CatalogPage.fromItem flattens entity metadata into a generic title, description and artwork. Album year, genres and the artist relationship do not reach the album header.
  • Artist pages use generic catalog sections. In that scoped path, section links may appear even when the full result is already shown.
  • The header displays “HOME › current page” while Back may return to search, an artist or another catalog. That label is not the actual navigation history.

The proposed rules

  1. Container → page. Source, catalog, folder, album, artist, playlist and collection open with one tap on their artwork, name or right chevron.
  2. Play → playback. A visible Play control starts music without opening a page. Navigation never changes playback.
  3. Track → play. Track rows use a play affordance and a separate overflow menu, never a navigation chevron.
  4. Back → previous place. Restore the query, filters, selected tab, loaded items, scroll position and focused item. A Home pin returns to Home; a search hit returns to its results.
  5. Disclosure stays within an item. “Read more” may expand a description. Albums and playlists never become nested track lists inside other listings.

Searching two or three music sources

Search is shared; music results retain their source and collections retain their user-owned identity. Design for a typical combination such as My Library + Qobuz, or My Library + Jamendo + Tidal. The interactive example uses My Library, Qobuz and Tidal with fictional overlapping catalogs. Try searching for Quiet Geometry: the same release appears from all three sources, with separate open and Play actions.

  • One results surface. Show merged name matches with the existing backend ordering and clear Artist / Album / Track / Playlist / Collection labels. Do not repeat a full Artists / Albums / Tracks browser for every source or add parallel source columns on tablets. Show four leading name matches, with an explicit All matches page for the rest. This keeps the suggestions reachable without a stack of separate Artists / Albums / Tracks shelves. The prototype uses a fixed illustrative order, not a new ranking algorithm.
  • One filter entry point. Keep the existing top-right search-and-filters pill. Its anchored panel edits the query, Name matching / Recommendations / Both, any combination of sources, and the available genres. Stage changes until Show results; Cancel, Escape, outside tap and Back discard them. Do not add a second page-wide source selector or Artists / Albums / Tracks tabs to search. The existing source shortcuts under Matches by name have a different, local purpose and remain within that section.
  • Chips explain the current combination. Show the query and removable applied-filter chips above results. Removing one chip clears only that choice; Reset all clears the filters and keeps the query. Within a facet, selections are alternatives; facets combine to narrow the search. Source and genre choices are remembered for the next query along with the response-kind selection. An older result visit still owns its original combination. This preserves the existing saved-selection behavior; it does not introduce named presets.
  • Keep Kalinka’s decision/receipt distinction. Selected options inside the filter panel use crimson fill with a check. Applied chips and the closed filter button remain neutral, with only the active-filter count in crimson. Genre options and support must come from the existing shared capability/vocabulary contract. The mock uses a small local fixture to demonstrate the controls; it does not define production genre matching or add provider-specific rules.
  • Retain the local source shortcut. The current All / source pills beneath Matches by name narrow only that mixed list. Recommendations remain unchanged. Show only sources with matching results after global filtering, hide this shortcut when only one source remains, and keep its choice per result visit rather than saving it as a global filter. This is distinct from the removable applied-filter chips beside the query.
  • Readable attribution. Mixed results show the source icon and name in secondary metadata. Keep names visible rather than relying on logos or colour alone. A dedicated album or artist page shows its source beside its identity, so every child row need not repeat it. Source names and artwork come from shared module metadata.
  • No inferred merging. Identical artist names or album titles remain separate source-owned entities. Open and Play use the exact returned ID; an artist link stays within that source. A future “Other sources” switch would require reliable cross-source identity and edition matching from the backend. No matching by title, implicit source substitution or silent playback fallback.
  • Independent availability. Keep successful results when another source fails, identify the unavailable source with Retry, and preserve scope choices even when that source has no matches. A filtered empty state keeps the applied chips visible and offers Edit search & filters. Loading and pagination remain per source; preserve stable ordering as results arrive rather than jumping the focused result around. Do not label loaded subtotals as complete counts.
  • Keep recommendations distinct. Every submitted request asks for both name matches and suggestions where supported. Show either response as it becomes available; never infer search mode from the words entered. Suggestions remain in source-ranked lists of up to 20 tracks per supporting source. Unsupported sources have no suggestion group, spinner or disabled heading. Search and ai_search support are independent of the catalogs capability that gates Home tiles.

On phones, applied chips wrap naturally below the query; with no filters there are no extra applied-filter chips to scan. On tablets, the filter panel is anchored below the top-right button and stays inside the browsing pane. Its body scrolls while Cancel and Show results remain reachable. This is the same filtering model for two sources or a larger installation.

Ranking remains a separate review decision. Clear types and attribution make the existing mixed list easier to read, but do not fix a weak ranking. Review real queries and results before changing the algorithm, grouping every entity into a separate shelf, or adding entity-type controls. The sample order is illustrative only.

Both responses to one smart search

The supplied current-screen screenshot already establishes the right structure. Retain its compact query-chip header rather than adding a second Search results hero. With Both selected, keep a stable order: Matches by name first when available, then Inspired by your request. A user can intentionally select only name matches or recommendations in the existing filter panel; no extra mode tabs or section-jump toolbar are needed. A mood or activity request may return only suggestions, and a precise artist name may still return both. The app does not decide which interpretation is correct.

Each suggestion source has its icon, name, actual count, Play all and Enqueue, followed by three track previews. All 20 tracks opens that source’s complete returned list as a normal page. Preserve the query, source, ranking and exact snapshot; Back restores the overview and position. A preview track starts the complete 20-track list at that track. Play all and Enqueue use only that source’s suggestions, never a merged queue across sources. There is no extra catalog level and this temporary result list is not pinnable as a catalog.

Loading, empty and failed responses are independent for each source and response kind. Suggestions can appear while name matching is still pending; do not block them on a global loading state. A failed name request does not hide successful suggestions from that same source. Omit successful empty groups; keep failed groups with Retry and pending groups with matching shimmers. “No results” is appropriate only when all applicable responses finish empty. A new query replaces both result snapshots together and ignores late responses from the previous query.

The prototype shows both responses and a name-only source using fictional capability fixtures, not claims about the deployed Qobuz or Tidal plugins. Try Quiet Geometry for both sections, music for a quiet evening for suggestions without name matches, and After hours for a collection plus suggestions. The geometric covers and suggestion lists are sample data, not semantic search results.

Collections are a separate searchable entity

Albums, artists, tracks, playlists and collections are distinct name-match types. A collection is a saved ordered list owned by the user; it may mix My Library, Qobuz, Tidal or any other source. Label its result Collection · 6 tracks and Mixed sources, using its cover or a track-artwork mosaic. Do not label it with the source of its first track or treat it as a provider playlist.

Search-origin filtering uses the existing source options, including the built-in collections origin. A collection result is owned by that origin, not by the source of its first track. Once opened, it shows its full contents with each track’s actual source; Play preserves the complete order and source-specific IDs. Search filters never trim the tracks inside it. An unavailable track is marked with its reason; do not silently substitute another provider’s recording.

Contract boundary: the current app represents collections as playlists. Preserve the existing built-in collection origin; if the generic row cannot distinguish ownership reliably, agree on a shared discriminator before adding a Collection label or template. Do not classify by a plugin name, the first contained track, or editability alone; a provider playlist may also be editable. No new collection search-type filter is required by this proposal.

Keep listening fast

This deliberately trades inline track expansion for one consistent detail page. Inspecting tracks takes one tap, and Back returns to the same spot. Starting an album still takes one tap through its Play control. The extra page has a purpose: it holds the release identity, metadata, full track order and artist links together, without making a search result into another nested browser.

Album and playlist cards and rows retain a visible Play button. Their overflow menus offer Play next and Enqueue. These actions do not navigate. The prototype simulates them in its player and queue; it sends no commands to Kalinka.

A track tap on an album, playlist or collection starts that track in the complete ordered container. A smart-suggestion track uses that source’s complete returned recommendation list. A track from mixed search results plays that track alone; it must not silently replace the queue with a five-item preview. Queue selection plays the existing queue occurrence. Explicit selection mode changes row taps to selection and visibly replaces the toolbar until Done or Cancel.

Define Play as starting a new playback context, Play next as insertion after the current item, and Enqueue as append. Do not interrupt playback while browsing, filtering, switching tabs or opening information. Announce pending playback and failures without optimistic navigation.

Keep actions capability-driven: open browsable items, show queue/play actions for addable items, and edit only editable collections. Preserve the existing module catalogs capability gate for Home sources. Do not guess actions or artist relations from provider names.

“View all” gets one meaning

It belongs only to a genuinely truncated preview on Home or a mixed catalog/search overview. It opens the complete listing with the same source, result kind, snapshot and filters; label it explicitly when useful, such as “All albums · 24”. Hide it when everything is already shown. On an artist’s Albums tab, scroll the complete paginated collection directly. Tabs switch content within that artist; they do not add Back steps.

Responsive and accessible behavior

Phones keep one browsing stack above the mini-player. Tablets keep that same stack in the right panel while the player stays on the left. Resizing preserves the active page, query, tab and position. No third browsing column or modal album pages. Sheets are reserved for actions and pin choices; search filters keep their existing anchored panel. Both stay within the active browsing panel.

Keep Playfair Display for entity titles, IBM Plex Sans for content, and uppercase IBM Plex Mono for shelf chrome. Use existing neutral surfaces, 32dp section spacing and round 48dp controls. Berry marks playback or a choice using the existing fill-or-outline rule. Square album covers remain intact; artist portraits may be circular. Large text wraps rather than shrinking. Back closes the top sheet first, then selection mode, then the page. Restore focus to the originating item and honor reduced motion.

Implementation sequence

  1. Unify the interaction contract. Route every browsable entity through the same open action across Home, search, source catalogs and collections. Remove container expansion controls and their global expansion state. Preserve explicit selection and collection editing.
  2. Preserve identity and navigation state. Introduce typed destination kinds with full BrowseItem metadata. Each visit owns query/filter/tab/scroll/focus and loaded pages. Use the existing notifier as the migration boundary; this does not require a router-package migration.
  3. Build the entity templates. Album, artist, provider playlist and mixed-source collection. Preserve the two smart-search response sections and source-specific suggestion-list destinations. Resolve artist tabs from declared relation types and stable IDs, never localized titles or provider names. Generic/unknown sections remain accessible by their returned labels.
  4. Make playback context reliable. Audit container expansion and stable start-track selection. The current replace-IDs + play-index sequence is separate calls and row playback can use only loaded IDs. Prefer an atomic backend context command with container/filter plus start-track identity and playlist occurrence ID; otherwise load/resolve the full context first, showing pending state. Never play a paginated subtotal as the whole album.
  5. Enrich details independently. Extend metadata through the shared SDK/API when necessary. Entity pages remain useful with today’s fields and never wait for optional credits or biographies.

Acceptance journeys

Smart-search checks: Both shows name matches and suggestions for the same query; a source without ai_search has no suggestion group; a suggestion preview plays the complete returned source snapshot. Collections preserve their full mixed-source order through search, playback and Back. Filter checks: choose My Library + Qobuz and Jazz, apply once, remove only Jazz, and confirm that both source choices remain. Cancel and Back discard staged edits. A new query remembers the applied combination, while Back restores the older result visit’s filters and position. Selecting the local Qobuz shortcut changes only Matches by name and is restored by Back; it never changes the saved global filter or hides My Library’s recommendation group. There are no entity-type tabs in search.

  • Filtered catalog → album → artist → another album → Back restores each exact page, then its filters and scroll.
  • Search → album → Back restores the query, applied filter chips and focused card.
  • Home pinned list and source catalog use identical album, artist, playlist and track interactions.
  • Play, Play next and Enqueue from a row leave the browsing page unchanged; selecting a track on page two never drops page one from its context.
  • Artist with only albums has no empty Tracks/About tabs. Failed relations show Retry; unavailable items explain why. Sparse metadata never produces blank labels or fabricated quality.
  • Duplicate tracks in a playlist resolve by occurrence; unknown duration is omitted; disabled sources do not destroy saved pins.
  • Phone ↔ tablet retains the route, filters, tab and scroll. Keyboard, system Back and gestures use the same dismissal order.
